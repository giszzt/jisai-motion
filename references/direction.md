# 动作设计与生成

## 从表达目的到时间关系

先写一句用户真正要表达的内容，再写 3–6 个动作阶段，最后分配姿态与时长。每阶段包括：主体变化、方向、重心/支撑、次级运动和停顿。不同帧可以细微变化，也可以有意停留；不追求每帧都是不同的展示姿势。

例如“困得睁不开眼”：正常注视 → 眼皮下沉 → 点头 → 惊醒 → 慢慢回到起始状态。只保留用户需要的情绪强度，不随意增加配件或剧情。

风格跟随参考或明确要求。身份锚锁定轮廓、面部、服装、材质、配色、附件和尺度；动作锚规定姿态轨迹，两者分开。多图有冲突时按指定角色分工，不把动作参考中的服装复制过来。

## 路线选择

先按表达关系识别动作单元：几个主体互相作用可能属于同一段动作，同一主体的多个独立用途可能需要分开。用户笼统要求一组动图但允许创作时，依据主题与用途补齐方案并陈述假设；只有缺口阻止判断目标时提问，不把任务变成固定人物批处理。单元可共享风格/材质/身份参考，但是否共表由运动范围、背景和可切分性决定。

空间规划先于生成：宽高覆盖动作最大展开（含文字变形、物体开合、离体附件、烟雾或光效），再用 layout.py plan 计算行列和总图比例。行列不由最终图集展示方式倒推。生成返回比例不支持原规划时换行列、分表或独立帧，不要求模型在不兼容画布中硬塞格子。多个相似单元先完整验证一个代表性样板；不同运动/背景风险不能用同一简单样板代替验证。

首次静态主参考图生成前先执行以下背景判断，后续整表、关键帧、补帧和修帧沿用同一策略：

1. 用户明确指定背景时优先执行，包括要求透明、指定场景或指定纯色底。
2. 用户未指定，但参考图包含主体所处的连续场景（如室内、街景、风景、桌面环境）时，默认延续该场景，保持跨帧布局、机位和照明稳定。多参考图按用途分工，仅作为风格或动作参考的背景不自动移植。
3. 其余情况默认真实 alpha 透明 PNG，包括纯文字、透明角色图、孤立主体参考。白色展示底、色卡、编号网格或棋盘展示底不等于连续场景，不自动保留或重画为背景。

默认透明时，兑现方式取决于后端，见 [生图后端](imagegen-backend.md)：

- 内置图像工具：第一张静态图的提示词就写明 `输出带真实 alpha 通道的透明背景 PNG；主体外为空透明区域，不添加场景、白底、色底、棋盘格、地台或背景投影。`
- Labnana API：这条通道没有 `background` 参数，只写提示词会换来一张把棋盘格画进像素的 RGB 图。改为要求纯色平底，抠图和 alpha 校验由 `generate_frames.py` 完成，键控子句由脚本追加，不要自己往提示词里写。

两条路都保留主体自身的材质和明暗，都检查 alpha 的实际透明像素；若失败，修复背景后再将其作为后续身份锚。

记录 `background_policy` 为 `transparent`、`user-specified` 或 `reference-scene`，以及 `background_reason`。这些是清单里的代理决策记录，不是生图 API 参数。透明策略对应 `require_transparency=true`；非透明场景对应 `false`。导出 MP4 时的底色只在合成阶段使用，不改变源静态图与 PNG 母版的默认透明策略。

| 路线 | 使用条件 | 失败处理 |
|---|---|---|
| sheet | 简单短动作、小尺寸、希望快速看到整体 | 布局失败重生成；少数姿态失败转局部修复 |
| keyframes | 高细节、大幅动作、明确关键姿态 | 主参考 + 两端关键姿态生成中间姿态，逐段验收 |
| sheet-repair | 已有可用整表且只有局部问题 | 一次修一个片段，保留其他合格帧 |

根据实际单帧尺寸决定布局。1024×1024 的 4×4 表只有 256×256/帧，放大不能补回细节。先决定需要多少独特姿态，再决定表格；不把导出帧率当作生成姿态数。

16 帧起优先规划 4K；不足 16 帧但细节多也可升档。记录目标单帧尺寸、返回总图尺寸、格子尺寸和扣除四边约 8% 安全区后的可用尺寸。该留白是初始实验默认值，不是逐帧缩放规则。头发、武器、离体物体、运动线和粒子也纳入完整运动范围。宽幅动作或像素不够时拆为每表 4–8 帧，沿用主参考、共享机位和尺度，检查分表衔接。按表数提前调整生成预算，不沿用一次序列调用假设。

普通表情/短动作可用 8 帧约 0.9–1.3 秒、16 帧约 1.8–2.6 秒、24 帧约 2.6–3.6 秒、32–36 帧约 3.5–5 秒作为待播放验证的起点。用户指定时间优先。新增中间姿态可以保持动作总时长；新增动作内容应重新分配阶段时间。快速发力与慢预备、结果停留分开安排，不把所有帧统一压到短时间。

原始动作表只有一个动作家族，等大单元、按行阅读、无编号/边框/文字。可用程序生成几何布局参考，但不以代码画出的角色代替生图。若用户只给已有表，保留其内容，不擅自重设计。

## 提示词骨架（按需要精简）

```text
任务：为 [用途] 创建 [主体] 的连续短动作画面。
参考：图 A 负责身份，图 B 只负责风格，图 C 只负责动作。
保持：具体外观、比例、材质、机位、照明不变量。
动作：按时间排序的阶段，每阶段 [姿态/方向/接触点/变化量]。
节奏：[慢预备、快速变化、适当停顿、恢复]，不是姿势展示合集。
构图：[画布比例、主体尺度、运动包络、安全边距]。
允许变化：[区域或部位]；其余区域保持稳定。
收尾：[单次结束/自然循环/停留后返回/适合的往返]。
布局：[行列数、顺序、单元尺寸要求]（整表才写）。
背景：默认真实 alpha 透明 PNG；仅按已确定的用户要求或参考连续场景例外保留背景，不画棋盘格模拟透明。
避开：裁肢、跨格、额外附件、身份变化、独立缩放、意外机位变化。
```

循环同时考虑姿态、运动方向、速度和次级运动。死亡、破碎、开门一般单次；倒放仅适合可逆运动。禁止用交叉淡化掩盖多余肢体。若原序列末帧与首帧重复，安排时长避免接缝双重停顿。

## 运动与对齐

共享画布、相机和站立等效尺度；不要把每帧外接框都缩放到同一大小。蹲下应更矮，伸手应更宽，跳跃应离地。接地动作可用固定支撑点，飞行物、火焰和跳跃不能套用脚底对齐。特效太大挤压主体时，按用途分层生成，第一版由代理安排合成，不声称脚本会自动拆层。

局部微动使用固定主参考反复编辑，明确允许变化的区域。若用户要求未动区域像素级不变，必须额外检验；不能只凭提示词承诺精确保留。

## 模型与声音

内置生图优先，保留可核验的工具/模型记录。内置工具不能选模型时，在生成前简短说明能力限制，沿用 host-managed 路线，不宣称强制选到了某个模型。没有内置图像工具的环境走 [生图后端](imagegen-backend.md)，默认 `flare`，要求精细度或清晰度更高时切 `sunburst`。不臆造 SDK 参数、凭据或收费回退。

声音以单动作总时长为边界。可复用已有音频或调用可用的 TTS skill；记录声音来源。脚本可把一个音轨从 0 秒开始合入 MP4，短音轨补静音，长音轨裁到动作结束。多音效偏移、配乐混音、字幕、口型对齐交给相应音视频工作流；不让处理脚本承担生图/生成声音。
