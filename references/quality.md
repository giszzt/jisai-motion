# 播放验收与修复

## 三层证据

检查顺序是实际源图布局→全部裁剪帧→解码播放。多单元扩展前，代表性样板必须完成整条链路，问题留在样板阶段解决。最终核对 motion.json、report.json、review.json 与编码产物；只有一份 GIF 或透明索引报告不构成验收。正式工具之外的编码没有自动受这些检查保护，不能借用工具测试通过来声称已验证。

1. 结构：清单合法、帧解码成功、尺寸统一、时间有效、交付文件可读。脚本会报告 alpha 范围、边界接触、重复帧、平均相邻差异、编码帧数和实际时长。
2. 画面：参考身份、附肢与附件、裁切、尺度、机位、局部不动区。查看整表和疑似问题单帧。
3. 时间：打开 preview.html 正常播放、半速、至少三个循环，在白/黑/棋盘背景检查透明残影。再直接打开 GIF/APNG/视频确认编码产物，而不是只看 PNG 播放器。

脚本只给结构证据和风险提示。不能由像素差异推断动作自然，也不能由 RGBA 模式推断背景透明。透明要求需 alpha 确实存在空区域；半透明发光有效，不应当作噪点全部删除。透明全空帧仅在有意的消失/特效尾部才允许，清单需显式打开 allow_empty_frames。

走 API 生图时 `generate_frames.py` 的 generation-record.json 是额外一层结构证据，`transparency.verified`、`keying.key_spill_fraction` 和整表的每格极差都要看。它证明 alpha 真实存在且键色没吃掉主体，不证明动作自然或身份一致，仍然要看图。

## 修复优先级

新切帧必须检查 layout-overlay.png 以及全部帧，不能只看 touches_edge。safe_area_risk 是待检查线索；框内部的邻帧残片也可能没有警告。opaque 场景的边缘内容通常合法，仍按场景判断。禁止默认按连通块质心归属、删除小碎块或逐帧外接框缩放，这些操作会损坏离体道具、粒子和跳跃。归属模糊或内容已经重叠时重生成。

各格背景占比极差会受姿态和特效范围影响，不能据此断言背景颜色不一致；keying_verified 也不能证明主体没有被误抠。需分别看背景颜色、主体完整性、软边和合法半透明特效。新版本没有改变抠图算法。

| 问题 | 最小修复 |
|---|---|
| 播放过急、停顿不足 | 改 duration_ms，直接重新 build |
| 少数身份或肢体错误 | 用主参考和邻帧局部重生成，替换清单中的路径 |
| 跨格/裁切 | 重生成该片段或原表，不裁掉主体凑尺寸 |
| 全局闪烁或机位变化 | 减少复杂度，重申光照/机位与主参考，必要时重生成 |
| GIF 脏边/残影 | 检查实际 alpha、调色板与 disposal；保留 PNG 母版，必要时提供 APNG/WebP |
| 主体边缘有键色残留或被啃掉 | 换键色重生成，不靠调阈值救；见 [生图后端](imagegen-backend.md) |
| 循环顿挫 | 检查端点速度和重复停留，修结束姿态；单次动作不强行循环 |

每次修改保留旧版，记录失败类别和变更，不自动无限重试。可重复静帧表达停顿；逻辑帧数与编码器合并后的帧数分开记录。若用户明确要求 16 个独特透明帧，交付前逐个确认 16 个实际不同姿态，不能用 8 张复制为 16 张。

## review.json

```json
{
  "status": "pending",
  "identity": "not_reviewed",
  "anatomy_or_structure": "not_reviewed",
  "motion_and_timing": "not_reviewed",
  "loop_seam": "not_reviewed",
  "encoded_playback": "not_reviewed",
  "backgrounds_checked": [],
  "issues": [],
  "generation_calls_used": 0,
  "keying_verified": null
}
```

完成实际检查后才改状态。结构不合格不得最终交付；视觉未检查可给预览但明确标为草稿。平台大小限制按用户目标当前规范检查，不写死未经验证的“平台合规”。
